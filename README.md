# Gravity

Полноэкранный 2D N-body симулятор на Kotlin/JVM. Все тела — белые точки размером
ровно 1 пиксель; весь основной монитор является открытым пространством.
Зума, интерфейса и столкновений нет. Тело, покинувшее экран, деактивируется и
больше не участвует в интегрировании, построении плотности и расчёте силы.
`Esc` завершает программу.

## Запуск

Нужны 64-битная Java 18+ и видеокарта с OpenGL 4.3 compute shaders.

```powershell
.\gradlew.bat run
```

Linux/macOS:

```bash
./gradlew run
```

По умолчанию симулируется фиксированное количество — ровно 350 000 тел; ёмкость
GPU-буферов также равна 350 000. VSync включён. Реальная частота кадров зависит
от GPU, драйвера, разрешения и распределения тел — программно гарантировать
60 FPS на любом железе невозможно.

Zero-padded FFT-поле по умолчанию прямоугольное — `1024×512`; экран занимает его
центральную область `512×256`. Нулевая внешняя половина превращает циклическую
FFT-свёртку в линейную, поэтому у пространства нет периодических копий и верх
экрана не взаимодействует с низом через шов. Физическая ширина автоматически
берётся из соотношения сторон монитора, поэтому гравитационное расстояние в
одном пикселе одинаково по X и Y.

### Начальная галактика

Начальное состояние детерминированно и настроено как устойчивая двухрукавная
спиральная галактика:

- 350 000 тел вращаются по часовой стрелке;
- диаметр равен 76% короткой стороны экрана, с безопасным отступом по 12% от
  верхнего и нижнего краёв;
- 1,5% общей массы находится в центральном массивном теле, 18,5% — в балдже,
  80% — в экспоненциальном диске;
- два логарифмических рукава имеют pitch angle 19° и небольшую дисперсию;
- круговая скорость каждого тела вычисляется из заключённой массы по
  двумерному закону `v² = G·M(<r)`, после чего добавляется малая дисперсия
  скоростей.

Для запуска с другим фиксированным количеством:

```powershell
.\gradlew.bat run --args="--bodies=500000 --capacity=500000 --grid=1024x512 --fixed"
```

Параметры: `--bodies=N`, `--capacity=N`, `--grid=WIDTHxHEIGHT`,
`--gravity=F`, `--softening=F`, `--dt=F`, `--fixed`, `--adaptive`. Режим
`--adaptive` явно включает автоматический подбор количества. Для короткой
диагностики есть `--frames=N`, после которой приложение само закроется. Те же значения
можно задать переменными `GRAVITY_BODIES`, `GRAVITY_CAPACITY`, `GRAVITY_GRID`,
`GRAVITY_G`, `GRAVITY_SOFTENING`, `GRAVITY_DT`, `GRAVITY_FIXED`.

## Вычислительная схема

Классический Barnes–Hut хорош для разреженных систем, но на равномерно заполненном
экране хуже отображается на SIMD GPU и имеет нерегулярный доступ к памяти.
Поэтому здесь используется более производительная разрешённая постановкой схема
P3M (Particle–Particle Particle–Mesh):

1. CIC-распределение массы четырьмя атомарными операциями в центральную половину
   zero-padded поля; неактивные тела пропускаются.
2. Настоящий radix-2 2D FFT плотности на GPU, без аппроксимации преобразования.
3. Спектральное умножение на заранее преобразованное свободное 2D Green kernel
   обеих компонент силы — без периодических копий источников.
4. Деконволюция двойного CIC-окна и гауссово Ewald-разделение.
5. Обратные 2D FFT и CIC-интерполяция поля.
6. Попарная поправка короткой части в разреженных spatial-hash ячейках и
   Barnes–Hut-монополь для плотных ячеек.
7. Симплектический kick-drift-kick (leapfrog) интегратор.

Средняя сложность шага — `O(N + M log M + N·k)`, где `M` — число узлов сетки,
а `k` — локальное число соседей. Чтобы патологический коллапс одной ячейки не
заморозил кадр, плотные ячейки агрегируются в массовый монополь, а собственная
ячейка использует ограниченную точную симметричную поправку; дальнее FFT
PM-поле при этом остаётся. Увеличение размеров `--grid` повышает спектральное
разрешение и расход GPU-времени/памяти. Обе стороны сетки должны быть степенями
двойки от 128 до 2048.

Позиции, скорости, ускорения, сетка, связанные списки и FFT остаются в VRAM:
между CPU и GPU каждый кадр частицы не копируются. LWJGL предоставляет GLFW и
OpenGL; JTransforms используется в тестах как независимый FFT-эталон.

## Проверка

```powershell
.\gradlew.bat test
```

Тесты проверяют параметры, регулятор количества тел и побитовую схему
прямоугольного 2D FFT против многопоточной библиотеки JTransforms.
