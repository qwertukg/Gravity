# Gravity

Полноэкранный 2D N-body симулятор на Kotlin/JVM. По умолчанию на весь экран
равномерно и независимо размещаются ровно 500 000 тел одинаковой массы. Каждое
тело отображается белой точкой размером 1 пиксель на чёрном фоне.

Физическое пространство имеет размеры экрана. Масштаб расстояния одинаков по X
и Y с учётом соотношения сторон монитора. При пересечении любой из четырёх
границ тело упруго отражается: нормальная компонента скорости меняет знак,
тангенциальная сохраняется. Коллизий между телами нет, тела не удаляются и не
фиксируются.

В левом верхнем углу поверх симуляции выводится ярко-зелёный FPS-счётчик.
`R` восстанавливает точное начальное состояние текущего запуска, `Esc` завершает
программу.

## Запуск

Нужны 64-битная Java 18+ и видеокарта с OpenGL 4.3 compute shaders.

```powershell
.\gradlew.bat run
```

Linux/macOS:

```bash
./gradlew run
```

По умолчанию количество тел фиксировано: `500000`; ёмкость GPU-буферов также
равна `500000`. VSync включён. Реальная частота кадров зависит от видеокарты,
драйвера и разрешения экрана — программно гарантировать 60 FPS на любом
оборудовании невозможно.

### Начальное состояние

Позиции тел равномерно случайны по всей ширине и высоте экрана, начальные
скорости равны нулю, массы одинаковы. При каждом запуске создаётся новый
криптографически случайный seed, который выводится в консоль. Клавиша `R`
повторно использует seed текущего запуска и точно восстанавливает его исходную
конфигурацию.

Для явного запуска со стандартной конфигурацией:

```powershell
.\gradlew.bat run --args="--bodies=500000 --capacity=500000 --grid=512x256 --fixed"
```

Параметры: `--bodies=N`, `--capacity=N`, `--grid=WIDTHxHEIGHT`,
`--gravity=F`, `--softening=F`, `--dt=F`, `--fixed`, `--adaptive`.
`--adaptive` явно включает автоматический подбор количества тел. Для короткой
диагностики есть `--frames=N`, после которой приложение само закрывается. Те же
значения задаются переменными `GRAVITY_BODIES`, `GRAVITY_CAPACITY`,
`GRAVITY_GRID`, `GRAVITY_G`, `GRAVITY_SOFTENING`, `GRAVITY_DT`,
`GRAVITY_FIXED`.

## Вычислительная схема

Для равномерно заполненного экрана используется GPU P3M
(Particle–Particle Particle–Mesh), совмещающий точное FFT-дальнее поле и
локальную поправку:

1. CIC-распределение массы четырьмя атомарными операциями.
2. Настоящий radix-2 2D FFT плотности на GPU без аппроксимации преобразования.
3. Спектральное умножение на заранее преобразованное свободное 2D Green kernel
   обеих компонент силы.
4. Деконволюция двойного CIC-окна и гауссово Ewald-разделение.
5. Обратные 2D FFT и CIC-интерполяция поля.
6. Точная попарная поправка короткой части в разреженных spatial-hash ячейках;
   плотные ячейки агрегируются Barnes–Hut-подобным массовым монополем.
7. Симплектический kick-drift-kick (leapfrog) интегратор и упругое отражение от
   границ.

Средняя сложность шага — `O(N + M log M + N·k)`, где `M` — число узлов сетки,
а `k` — локальное число соседей. Плотные ячейки агрегируются, чтобы локальный
коллапс не замораживал кадр; дальнее PM-поле при этом сохраняется.

По умолчанию zero-padded FFT-сетка прямоугольная: `512×256`, её центральная
физическая область — `256×128`. Нулевое дополнение превращает циклическую
FFT-свёртку в линейную, поэтому гравитационное поле не получает периодических
копий с противоположной стороны экрана. Отражающими являются только границы
движения частиц. Обе стороны сетки должны быть степенями двойки от 128 до 2048;
увеличение сетки повышает пространственное разрешение и расход GPU-времени и
памяти.

Позиции, скорости, ускорения, сетка, связанные списки и FFT остаются в VRAM:
между CPU и GPU частицы каждый кадр не копируются. LWJGL предоставляет GLFW,
OpenGL и STB Easy Font для FPS overlay. На Windows JNA запрашивает нативный
foreground-фокус полноэкранного HWND до первого содержательного кадра, чтобы HDR
активировался без клика. JTransforms используется в тестах как независимый
FFT-эталон.

## Проверка

```powershell
.\gradlew.bat test
```

Тесты проверяют параметры запуска, регулятор количества тел, равномерную
инициализацию, случайность seed, точное воспроизведение начального состояния и
побитовую схему прямоугольного 2D FFT против многопоточной библиотеки
JTransforms.
