# Gravity

Полноэкранный 2D N-body симулятор на Kotlin/JVM. По умолчанию на весь экран
равномерно и независимо размещаются 100 000 тел одинаковой массы. Каждое тело
отображается точкой размером ровно 1 пиксель на чёрном фоне. Цвет показывает
контактное давление плавно проходит длинный путь HSV: голубой → зелёный →
жёлтый → оранжевый → красный при фиксированном пределе `64 px/s`. Более
высокое давление также отображается красным.

Тела считаются круглыми и имеют абсолютно неупругие контакты (коэффициент
восстановления равен нулю), не сливаются и не удаляются. Пиксельная контактная
сетка используется только для поиска соседей и не позволяет телам проходить
друг сквозь друга. Контактный диаметр по умолчанию равен `1.12838` пикселя
(`2/√π`), поэтому геометрическая площадь круглого тела равна `1 px²`, а площадь
сгустка из 400 000 тел стремится примерно к 400 000 пикселям. На движение
продолжают влиять гравитация и ускорение.

В левом верхнем углу поверх симуляции выводится ярко-зелёный FPS-счётчик.
`R` восстанавливает начальное состояние текущего запуска, `Esc` завершает
программу.

## Запуск

Нужны 64-битная Java 18+ и видеокарта с OpenGL 4.3 compute shaders.

```powershell
.\gradlew.bat run
```

Linux/macOS:

```bash
./gradlew run
```

Начальное количество тел по умолчанию равно `100000`, ёмкость GPU-буферов —
`400000`. Число тел не меняется во время запуска. VSync отключён. Реальная
частота кадров зависит от видеокарты, драйвера и разрешения экрана.

Для явного запуска стандартной конфигурации:

```powershell
.\gradlew.bat run --args="--bodies=100000 --capacity=400000 --grid=512x256"
```

Поддерживаемые параметры:

- `--bodies=N` — начальное количество тел;
- `--capacity=N` — ёмкость GPU-буферов;
- `--grid=WIDTHxHEIGHT` — размер FFT-сетки;
- `--gravity=F` — гравитационная постоянная;
- `--softening=F` — смягчение в ячейках сетки;
- `--dt=F` — шаг симуляционного времени;
- `--collisions=N` — число итераций контактного решателя (1–16);
- `--diameter=F` — контактный диаметр тела в пикселях;
- `--pressure-max=F` — фиксированное давление для красного цвета;
- `--square-test=WIDTH` — плотный квадрат для диагностики;
- `--frames=N` — завершение после заданного числа кадров;

Те же основные значения задаются переменными `GRAVITY_BODIES`,
`GRAVITY_CAPACITY`, `GRAVITY_GRID`, `GRAVITY_G`, `GRAVITY_SOFTENING`,
`GRAVITY_DT`, `GRAVITY_COLLISIONS`, `GRAVITY_DIAMETER` и
`GRAVITY_PRESSURE_MAX`.

### Начальное состояние

Позиции тел равномерно случайны по всей ширине и высоте экрана, начальные
скорости равны нулю, массы одинаковы. При каждом запуске создаётся новый
криптографически случайный seed, который выводится в консоль. Клавиша `R`
повторно использует seed текущего запуска.

`--square-test=632` размещает 400 000 тел по одному на уникальный пиксель в
области 632×633. В последней строке остаётся 56 свободных пикселей:

```powershell
.\gradlew.bat run --args="--bodies=400000 --square-test=632 --frames=2400"
```

После конечного запуска печатаются площадь по ковариации, оценки области для
90% и 99% тел и максимальная скорость.

## Вычислительная схема

Гравитация рассчитывается на GPU по схеме P3M
(Particle–Particle Particle–Mesh):

1. CIC-распределение массы по сетке.
2. Radix-2 2D FFT плотности без аппроксимации преобразования.
3. Спектральное умножение на преобразованное свободное 2D Green kernel.
4. Деконволюция двойного CIC-окна и гауссово Ewald-разделение.
5. Обратные 2D FFT и CIC-интерполяция дальнего поля.
6. Точная попарная поправка короткой части в разреженных spatial-hash ячейках;
   плотные ячейки агрегируются массовым монополем.
7. Симплектический kick-drift-kick (leapfrog) интегратор.
8. Пиксельный spatial hash, контактные подшаги и Jacobi-коррекция проникновения.
   Нормальная относительная скорость гасится без отскока, а коррекция позиции
   преобразуется в давление через `Δv = Δx/Δt`. Все попарные веса симметричны,
   поэтому тела обмениваются скоростью без потери суммарного импульса.

Средняя сложность шага — `O(N + M log M + N·k)`, где `M` — число узлов
FFT-сетки, а `k` — локальное число гравитационных соседей. Контактный решатель
имеет среднюю сложность `O(N)` при плотности около одного тела на пиксель.

По умолчанию zero-padded FFT-сетка прямоугольная: `512×256`, её центральная
физическая область — `256×128`. Нулевое дополнение превращает циклическую
FFT-свёртку в линейную, поэтому гравитационное поле не получает периодических
копий с противоположной стороны экрана. Обе стороны сетки должны быть степенями
двойки от 128 до 2048.

Позиции, скорости, ускорения, гравитационная и контактная сетки, связанные
списки и FFT остаются в VRAM:
между CPU и GPU частицы каждый кадр не копируются. LWJGL предоставляет GLFW,
OpenGL и STB Easy Font для FPS overlay. На Windows JNA активирует нативный
foreground-фокус полноэкранного окна до первого содержательного кадра.

## Проверка

```powershell
.\gradlew.bat test
```

Тесты проверяют параметры запуска, инициализацию, случайность seed,
воспроизведение начального состояния и прямоугольный 2D FFT
против JTransforms. Отдельный тест инициализатора проверяет 400 000 уникальных
пикселей в области 632×633.
